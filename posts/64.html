AI2026年11月9日约 6 分钟

据传 ChatGPT 开始大规模封号，是真的吗？原因可能是什么？

三个人合拼的一个 Team 席位，一夜之间全部失效了。这不是孤例：11 月 7 日，OpenAI 大规模停用了一批拼车号、反代号和低价区号。

答案可以浓缩成一句话：包月不限量的订阅模式，前提是人的使用量有上限，而 Codex 这类编程 Agent 把这个前提打破了。封号、新政策、计费方式切换，是同一条线上的几个点。先把现象摆出来：低价区、拼车、反代、学生认证这几类是重灾区。

包月不限量为什么以前能成立

ChatGPT Plus 一个月 20 美元、基本不限量。这个模式能跑通，依赖的是人的使用量天然有上限：打字、读回答都要时间，人还得吃饭、睡觉、上班，再重度的用户一天也就聊几个小时。总有大量用户付了钱却用不满，重度用户的成本由他们分摊，平台整体是赚钱的。

过去几年拼车、共享账号一直存在，OpenAI 基本睁一只眼闭一只眼：三个人合用一个 Plus，消耗也就是三个人的聊天量，没有超出这个模式能承受的范围。

Agent 打破了什么

Codex 这类编程 Agent 普及之后，消耗和人的时间脱钩了。给它一个任务，它可以自己读仓库、跑测试、改代码，循环几十轮，工程师去睡觉了，它还继续跑。一个重度使用 Codex 的开发者，按 API 价格折算，一个月用掉的 token 可能是订阅费的好几倍，有人估算能到十几倍。这个数字是根据社区里一些人晒的账单粗略推的，具体还得看用法，但量级差距是真实存在的。

套利链条：反代与低价区

codex2api 这类工具就是这时候冒出来的：把订阅账号的 Codex 额度逆向包装成标准 API 接口，再分发给别人调用。拼车只是几个人分摊一份消费级服务，而反代是把消费级价格的算力搬到开发者市场去卖，直接和 OpenAI 自己的 API 业务抢客户。

低价区又叠了一层。土耳其、菲律宾、埃及的订阅价格本来就低，用低价区账号接反代再转卖，中间有两层价差。去年我见过一些中转站的报价，比官方 API 还便宜一大截。

OpenAI 最近一个月的动作

把官方近期的动作按时间排一下，封号的性质就比较清楚了： 11 月 2 日前后，同一设备、同一张支付卡可绑定的付费订阅设上限，针对一人多开、叠号； 11 月 7 日，大规模停用拼车号、反代号、低价区号，清理存量违规账号； 11 月 20 日，新版使用政策生效，第三方 API 网关和模型路由中介必须取得官方书面授权，指向中转站的合法性； 12 月起，Plus、Pro、Business 的 ChatGPT 与 Codex 共用额度、按 Token 计量，动的是包月制本身。

ChatGPT 和 Codex 合并额度、按 Token 算之后，订阅就从按人收费变成了按量收费，套利空间基本消失。所以这波封号，应该是新规则上线前对存量账号的一次清理：规则切换期间最容易出现大量账号同时迁移、批量注册的情况，提前处理掉，后面的计量体系就干净了。

另有一个背景是模型蒸馏。OpenAI 此前公开过阻断大规模提取模型推理内容的行动，新版政策也明确限制用模型输出训练替代模型，而反代渠道恰好是蒸馏者最方便拿到大量低价调用的地方。

误伤问题

风控系统看不到用户的动机，只分析行为特征：调用频率、持续时长、设备数量、IP 是否频繁切换、额度消耗曲线。问题在于，一个认真用 Codex 写项目的独立开发者，和一个跑反代分发的账号，在这些指标上可能非常接近——都是高频、长时间、大消耗。如果再用了不稳定的代理节点，IP 一会儿在新加坡一会儿在日本，被识别成异常账号的概率就更高。

今年 6 月那次误封，OpenAI 官方承认是系统问题，后来恢复了账号并给了补偿。这一次，截至写作时官方还没有任何公开说明。平台有权清理违规账号，但对付了几年钱的 Pro 用户，连一封说明邮件都没有就直接删号，这种处理方式确实说不过去——很多人的工作流、Custom GPT、几年的对话记录都在账号里。

后续走向

包月不限量的模式在 Agent 时代肯定会逐步退出。不只是 OpenAI，Anthropic 之前也对 Claude Code 订阅被第三方工具调用的问题做过限制，方向是一样的。以后比较可能的形态是基础订阅加按量计费，或者分档的 Token 包：只要 Agent 的消耗不再受人的时间限制，固定价格就很难覆盖成本。

中转站要么拿到授权，要么消失。11 月 20 日之后，没有授权的中介在政策层面就是违规的；规模较大的可能去申请成为官方渠道，小的基本没有空间。依赖中转站的国内开发者，接下来需要认真比较官方渠道、云厂商代理和国产模型的成本——对国产模型来说，这算是个好消息。

账号本身已经是生产资料，数据可携带会成为新的诉求。这次封号影响最大的是长久积累的聊天记录、记忆和项目上下文，估计接下来会有更多人要求平台提供完整的导出和迁移能力。

给还在用的人几个建议

定期在设置里导出数据；不要把客户交付相关的工作流押在一个账号上；尽量用稳定的网络环境，不要频繁切换节点；如果被误封，走官方申诉表单，写清账号信息和报错里的 Request ID，之前确实有人这样申诉回来了。

最后只下一个有分寸的判断：对依赖拼车和中转站的人来说，白用和拼车的日子基本算是结束了；至于这轮封号的具体范围和误伤比例，在 OpenAI 给出公开说明之前，外界能做的只有依据时间线和个案推断。
