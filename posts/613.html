下了班，公司的大模型额度还能接着用：magpie + Tailscale 网关实战

现在不少公司都在搞 Token 竞赛，给员工配置免费的国外大模型 API Key（AK）——额度大、模型全，不用白不用。但这类 AK 有个硬约束：只能在公司电脑上、连着公司局域网才能调用。下了班回到家，个人笔记本、手机上的 Claude Code、Codex、Cursor、OpenClaw 全都用不上这波免费额度，只能自己掏钱买订阅。

解法其实很直接：让公司 Mac 当唯一的网关宿主，个人设备从外网安全地连回去调用。

整套架构是「AK 只留在公司 Mac + magpie 本地网关 + Tailscale 加密直连」：公司发的 AK 只配置在公司 Mac 的 magpie 里，magpie 只监听本机回环、对办公局域网零暴露；再用 Tailscale 的 serve 功能把这个本地网关定向转发给你自己的 Tailscale 账号设备。你的个人笔记本、手机无论在哪，只需把 Base URL 指向公司 Mac 的 Tailscale HTTPS 域名、填一把网关密钥，就能调用公司 Mac 上的全部模型——请求从你的设备加密直达公司 Mac，再由公司 Mac 带着 AK 去访问上游，链路和在工位上用没有任何区别。

本文完整拆解这套方案：magpie 网关部署、零暴露的监听配置、Tailscale 组网与 serve 转发、下班后的防休眠保活，以及各主流 Agent 的接入写法。

先把边界说清：公司 AK 的使用范围（设备、网络、用途）以公司明文规定为准。这套架构解决的是「怎么连得回去」的技术问题，连回去之后算不算违规、会不会被审计，各家口径不同——调用日志在公司侧是留痕的，先摸清规则再动手，别让羊毛变成合规事故。

一、为什么选择 magpie 作为网关核心？

在这套架构里，magpie 是装在公司 Mac 上的那一层网关，它的几个特性正好对症：

  • - 多协议自动转换：默认在 3425 端口运行统一网关，原生支持在 OpenAI、Anthropic 和 Gemini 三大协议间自动转换。公司发的一套 AK，可同时喂给 Claude Code、Codex、Cursor 等所有主流 Agent。
  • - 独立的网关密钥体系：可以为每台个人设备单独签发一把专属网关密钥（sk-magpie-...），随时单独吊销。真实的公司 AK 始终只存在于公司 Mac 上，个人设备上存的只是可吊销的网关密钥。
  • - 精细化额度与权限控制：支持按设备/密钥单独设定每日、每周、每月的 Token 与花费上限，以及限制该设备允许调用的模型列表。给手机签发的密钥就可以只开放轻量模型、设低额度。
  • - 统一的调用日志与路由组：所有个人设备的请求都在公司 Mac 的 magpie 里集中记录；公司轮换 AK 或调整渠道时，只需在公司 Mac 上改一次，全设备即刻生效，个人设备零改动。

二、公司 Mac 端：部署 magpie 网关（零暴露）

办公环境人多设备杂，宿主配置的核心原则只有一条：magpie 不对办公局域网开放任何端口。它只监听本机回环 127.0.0.1，外部访问全部走第三章的 Tailscale 定向转发。

2.1 装好 magpie 并录入公司 AK

  1. 1. 在公司 Mac 上安装 magpie，把公司发的 AK 按供应商录入（OpenAI / Anthropic / Gemini 渠道照常添加），在公司 Mac 本地先用任意一个 Agent 验证能正常调用。
  2. 2. 切换到「网关（Gateway）」页面，为每台要接入的个人设备各生成一把独立的网关密钥（如「我的笔记本」「我的手机」），按需设定消费上限与可调用模型范围。密钥形如 sk-magpie-...，先保存好，第三、四章要用。

2.2 保持关闭局域网共享，锁定回环监听

  1. 1. 进入 magpie「设置（Settings）→ 网络与共享」，确认局域网共享保持关闭。这样 magpie 只监听 127.0.0.1:3425，办公局域网里的其他机器扫不到、连不上这个端口。

确认输出中的 NAME 列显示为 127.0.0.1:3425 (LISTEN)，而不是 *:3425。这一步是整个零暴露架构的验收点，务必亲眼确认。

三、用 Tailscale 把网关定向转发给个人设备

公司 Mac 上的 magpie 只听本机回环，个人设备要连回去，靠的是 Tailscale：它为你的设备组建一层基于 WireGuard 的点对点加密虚拟内网，再用内置的 serve 功能把本机端口以 HTTPS 形式仅向你自己账号下的设备开放。

3.1 组网与防过期设置

  1. 1. 在公司 Mac 以及所有个人设备（笔记本、手机等）上安装 Tailscale，使用同一个个人账号登录。
  2. 2. 打开 Tailscale 管理后台（Machines 页面），找到公司 Mac，点击右侧「...」→「Disable key expiry（禁用密钥过期）」，防止 180 天后公司 Mac 在无人值守状态下自动离线。个人设备同理可设。
  3. 3. 在管理后台的 DNS 页面开启 MagicDNS 与 HTTPS Certificates——下一步 serve 签发内网 HTTPS 证书要用。

四、下班后的保活：锁屏可以，休眠不行

个人设备晚上连回去时，公司 Mac 必须醒着且联网。macOS 锁屏（Control + Command + Q）不会中断后台的 magpie 与 Tailscale 服务，但系统深度休眠或笔记本合盖会直接断网，下班前按宿主类型处理：

  • - 台式机（Mac mini / Mac Studio / iMac）：进入「系统设置 → 节能」，关闭自动休眠（勾选「防止自动进入睡眠」）。
  • - MacBook：留在工位插电运行、不要合盖，离开前在终端运行系统内置的防休眠命令（允许屏幕熄灭，保持系统与网络在线）：

六、高频排错与避坑清单

配置完成后如果遇到连接失败或调用报错，可按以下表格快速定位：

【Connection refused】 常见原因：公司 Mac 上 magpie 未启动，或 serve 转发失效 排查与解决：在公司 Mac 执行 `lsof -nP -iTCP:3425 -sTCP:LISTEN` 核对端口监听；运行 `tailscale serve status` 检查转发是否在运行。

【能连上但延迟明显偏高】 常见原因：Tailscale 走了 DERP 中继（办公网络拦截 UDP 打洞） 排查与解决：`tailscale status` 看是否显示 `via DERP`；中继只影响延迟、不影响可用性，日常对话可接受，无法打洞时无解、不用折腾。

【开启 Clash / Surge 后域名不通】 常见原因：代理软件的 TUN 模式或 Fake-IP 劫持了 Tailscale 网段 排查与解决：在 Clash / Surge 分流配置中，将 `100.64.0.0/10` 和 `*.ts.net` 加入 DIRECT 规则，同时添加到 fake-ip-filter（跳过 Fake-IP）与 TUN 路由排除列表。

【报 404 Not Found】 常见原因：协议路径多了或少了 /v1 排查与解决：OpenAI 兼容客户端末尾需带 `/v1`；Anthropic（Claude Code）与 Gemini 指向根路径，不要手动拼 `/v1`。

【报 401 Unauthorized】 常见原因：网关密钥填错、被禁用或触达额度上限 排查与解决：到公司 Mac 的 magpie「网关 → 网关密钥」核对密钥状态，以及是否超出了设定的日/周/月花费上限。

【白天能用、下班后突然断连】 常见原因：公司 Mac 进入睡眠、合盖，或 Tailscale 密钥满 180 天过期 排查与解决：按第四章做防休眠（或运行 `caffeinate -dims`）；到 Tailscale 后台确认已勾选 Disable key expiry。

【公司 VPN 一开就连不上】 常见原因：办公 VPN 与 Tailscale 路由冲突 排查与解决：先开 VPN 再开 Tailscale，用 `tailscale status` 确认公司 Mac 在线状态；多数情况下 DERP 中继可兜底连通。

结语

这套架构理顺之后，公司发的 AK 只需要录入公司 Mac 一次：轮换 AK、调整渠道、增减模型，都只在公司 Mac 的 magpie 里改一处；个人设备上存的永远是可单独吊销的网关密钥。无论你是在家里的笔记本上写代码，还是在路上用手机让 Agent 跑个任务，调用的都是公司 Mac 上那套免费额度——一次配置，全设备通用。
