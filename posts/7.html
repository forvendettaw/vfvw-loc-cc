GitHub 上最近有个叫 REA 的项目火了

@protonpoker
AI2026年11月4日约 2 分钟
18px
阅读进度 0%

GitHub 上最近有个叫 REA 的项目火了，全称 Reverse Engineer Anything——让 AI 帮你逆向分析几乎任何软件，甚至照着分析结果把功能重新实现一遍。

第一次看到这个名字时，我脑子里冒出一个夸张的念头：以后是不是看到什么软件，就能自己做出什么软件了？ 以前想研究一个 App 的某个功能是怎么实现的，只能自己猜架构、查资料、研究接口，运气不好折腾几天也没有头绪。现在情况有点不一样了。REA 可以接入 Claude Code、Cursor、Codex 这类 AI 编程工具，让 AI 帮你分析软件的内部结构、模块关系和调用逻辑，甚至包括编译后的程序。

最让我感兴趣的是，它不止停留在分析层面，还能让 AI 根据分析结果，尝试把某个功能重新实现出来。

我把最简单的上手流程整理了一下。

第一步，准备好 Node.js，以及一个 AI 编程工具，比如 Claude Code 或 Cursor。

第二步，打开终端，运行：

npx rea-agents setup

按提示选择你要用的 AI 编程工具，完成配置后重启。

第三步，找一个自己的开源项目、或者有授权的软件，选定你想研究的那个功能。

第四步，直接告诉 AI：

“使用 REA 分析这个软件的搜索功能，解释模块结构、数据流和关键逻辑，给出证据，再用 React 帮我独立实现类似功能。”

第五步，让 AI 生成代码，在本地运行、测试，再逐步完善。

如果需要分析原生程序，还可以配置 Ghidra 这类专业逆向工具。整套流程走下来你会发现，过去得靠自己反复翻找的技术线索，现在 AI 可以帮你整理出来。

当然，也要说清楚它不是什么：它不是一键复制任何 App 的魔法。复杂业务、服务端系统、安全机制和产品体验，仍然需要真正的工程能力；别人的专有代码，也不是可以随便复制的东西。

但真正有意思的变化在于，过去开发一个产品，大量时间花在“研究别人是怎么实现的”上，而现在 AI 正在帮我们缩短这个过程。未来的软件开发，可能不再只是从零开始写代码，而是先研究成熟产品，再设计自己的实现。

看懂一个软件，和造出一个软件，这两件事之间的距离，正在被 AI 一点点缩短。这才是我觉得 REA 最值得关注的地方。
